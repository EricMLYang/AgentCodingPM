開發出 Claude Code 前，Boris Cherny 曾在奈良過著釀味噌的生活
󠀠
上個月 Claude Code 團隊來到日本舉辦 Code with Claude 東京場，Claude Code 的創造者、現任負責人 Boris Cherny 也有來。聽了他分享才知道，原來他在加入 Anthropic 之前，曾經在日本住了將兩年多，而且住的不是東京這種國際大城市，而是在關西的古都奈良。
󠀠
好奇心使然，看了一下 Boris 在那時期的社群媒體發文，不像現在都是技術相關的更新，幾乎都是今天又做了什麼味噌、經過多次嘗試總算自己成功種出大根 (白蘿蔔)、日本的故鄉納稅制度讓自己拿到 18 顆來自北海道的新鮮牡蠣。
󠀠
當提到軟體工程師，多數人第一時間會想到矽谷這個詞；甚至在社群中很常會聽到，要做出有影響力的成果，就要搬到矽谷。這類觀點的論點是矽谷是軟體業的主舞台，有最多資訊、有最密集的人脈網絡。但 Boris 的經驗卻非如此，即使在一個滿是寺院、鹿與歷史的古都，他也能有效地發揮影響力。
󠀠
爬了一下 Boris 的個人部落格，可以看到他搬到日本一年半後寫的 《Learning to work (very) remotely》一文。在進到 Anthropic 之前，他在 Meta 底下的 Instagram 擔任首席工程師 (E8)，這是一個非常重團隊層級貢獻與影響力的職位。然而，因為身處在一個特別的時區，他難以配合矽谷、紐約、倫敦等地的會議。
󠀠
一般來說，在大型公司沒辦法參與會議，這可能意味著自己會逐漸被邊緣化，難以發揮被期待要有的影響力。最開始 Boris 也確實遇到這種困境，特別是自己被從某些重要專案的關鍵路徑上移除，他說自己甚至感到有一點受傷。
󠀠
因為難以參與會議，讓 Boris 多出了很多時間。他曾經嘗試過幾個不同的方向，包含跟其他在東京辦公室的工程師一起嘗試新的產品想法、指導新加坡辦公室的工程師。雖然在時區上能配合，但這些嘗試沒有想像中容易。例如他雖然能配合新加坡辦公室的時區，但對那邊正在發生的事情缺少脈絡，因此很難真正成為一個好的導師。
󠀠
不過也正因為每天不再是充滿會議的行程，他開始有時間重新開始寫程式碼。在業界有一種說法，當工程師越往上爬，越少時間能寫程式。特別是當到 E8 職級的首席工程師，會被預期影響力是跨組織的，所以即使是個人貢獻者 (IC)，行程也很常會被各種會議淹沒。而沒辦法參與會議的 Boris，笑稱自己某種程度上，把自己變回一個實習生，一天有超過 80% 的時間在寫程式。
󠀠
他開始分析 Instagram 程式碼庫的痛點，幫忙把程式碼庫改得更乾淨、幫忙改善基礎設施讓其他工程師更有生產力、幫忙修掉那些其他工程師覺得難以解決的問題。漸漸地他在 Instagram 內建立起「大家覺得 Boris 是熟悉程式碼庫、而且有不錯技術判斷的工程師」的名聲。於是，住在奈良做味噌的日子，反倒讓 Boris 成為 Instagram 前百分之一程式碼提交量的工程師。
󠀠
除此之外，Boris 也調整了自己帶專案的方式。從過去站在前方，轉為「在幕後領導」。他會把想做的事拆成多個專案，找美國和歐洲、中東、非洲地區的工程師來主導，並且當專案長出大量溝通或協調需求時，讓其他工程師接手。從自己親力親為轉為授權 (delegation)，他協助那些正在成長期的資深工程師，成為專案的公開門面。
󠀠
雖然不再是自己主導，他在 Instagram 的聲譽卻持續成長，組織裡的工程師和主管不只知道 Boris 在做什麼，也欣賞他替其他人創造機會，以及這些工作對 Instagram 帶來的影響。
󠀠
與此同時，他開始調整自己的溝通方式。不再試著把過去那套工作方式硬套到新的環境裡，而是開始利用自己奇怪的時區。Boris 不再透過聊天工具快速來回溝通，而是在早上集中處理累積下來的訊息，並且每天用第一個小時寫比較長、比較完整的回覆。他總是預先想清楚，聊天另一端的人真正想問的是什麼、可能會怎麼回應，以及還需要知道哪些資訊。透過花時間寫出更好的回覆，Boris 替雙方都避開了很多耗時的來回溝通。
󠀠
因為難以配合會議，他也轉成使用 Meta 內部版的群組貼文來分享想法、發起討論和發布公告。這樣讓溝通變得對不同時區的人更友善，對那些原本不會被邀請進會議，或即使進了會議也不一定敢開口的人，也更包容。
󠀠
看到 Boris 的分享真的讓人很有感觸，影響力這件事可能發生在任何地方；特別對軟體工程師來說，只要用對方法，完全可能跳脫某個既定的框架後仍持續創造影響力與價值。
󠀠
在奈良的那段時光，除了因為調整工作方式，讓自己持續發揮影響力。在後來的訪談中，Boris 也曾談過做味噌的經驗，教會他用更長期的方式去思考。他提到，白味噌要釀三個月，紅味噌甚至要兩到三年，今天做的不是今天吃，而是為了未來某一天而做。
󠀠
這種時間尺度也體現在後來 Claude Code 的開發哲學上。Claude Code 團隊不是為今天的模型，而是為下一代的模型來構想與開發新功能。
󠀠
在爬梳 Boris 的分享時，我們也不禁反思。現在每個人都能輕易地呼叫多個 AI 代理來實作，但在現行社群風氣下，這種容易取得的能力，反而讓很多人更容易求快不求遠。也許我們都可以多從釀味噌這件事學一點，用更長遠的眼光來用 AI，不是急著做出更多一次性的 AI 垃圾，而是細細打磨那些長期能持續創造價值的東西。
